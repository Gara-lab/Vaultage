# Real MVP planning

## Summary
The user confirmed the real, non-mockup MVP web-app will be built soon, so the project's
`planning` skill was run to produce a full spec for it, written into a new `mvp-plan/`
subfolder rather than at the project root (keeps it separate from the mockup's own
ARCHITECTURE.md/CONTRACTS.md). No application code was written and `seed/` was not
touched, per explicit instruction that scaffolding "won't be for now." Nine artifacts were
created (project.md, requirements.md, data-model.md, architecture.md, contracts.md,
workflows.md, testing.md, decisions.md, risks.md), carrying forward every confirmed
mockup invariant (FIFO consumption, stocktake loss-only, 14-day reorder horizon, 30-day
dead-stock threshold) rather than re-litigating them. Separately, the whole vault was
delinked/decluttered by adding `[[wikilinks]]` across all ~12 projects, and
`system_workflow_template/V4` was verified (not recreated) as already a correct, current
capture of this project's reusable optimizations over V3.

## Decisions
- Real MVP stack: Node.js/Express backend, PostgreSQL, low-ops PaaS hosting.
- Multi-tenant: many isolated shops, one shared login per shop (no per-staff roles),
  self-serve public signup.
- Tenant isolation (every table/query scoped by `shop_id`, session-derived only, never
  client-supplied) promoted to the plan's top contract and top risk.
- Assumed (not confirmed): no existing mockup data needs migrating, session-cookie auth
  over JWT, bcrypt/argon2 hashing, inline base64 icon storage, no password reset in v1.
- Real MVP scaffolding/implementation is explicitly deferred — planning only, for now.

## Open items
- Whether/when to scaffold the real MVP project from `system_workflow_template/V4`.
- Password reset, multi-staff roles, multi-location, and billing all deferred (see
  `mvp-plan/risks.md`).
