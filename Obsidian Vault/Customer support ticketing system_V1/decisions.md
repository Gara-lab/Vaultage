# Decisions

- **2026-09-22** — This project (`Customer support ticketing system_V1/`, living inside the `Codex_V1` factory-root workspace under `Bureau\AI\Ideas\Promotional shoot`) is a separate lineage from the older "Customer support ticketing system" vault project (which relocated to `system_workflow_template\Codex_V1` and `Luminara_V1`). Logged here under its own project name rather than merged into that older history, since the two live at different paths and may have diverged.
- **2026-09-22** — `Codex_V1`'s active focus is this sub-project; the earlier RWKV-7/stigmergy "ants" decision logged in the factory-root `AGENT_LOG.md` belonged to a different, unrelated prior project and was removed.
- **2026-09-22** — Full-site FR/EN language toggle: French is the default language, choice persists via `localStorage`, built with a hand-written `js/i18n.js` dictionary module (no i18n library — ponytail ladder: ~70 short UI strings didn't justify a dependency). Toggling reloads the page rather than live re-rendering, since every page already regenerates its dynamic content from scratch on load.
- **2026-09-22** — Knowledge-base articles (`data/kb.js`) store bilingual content as a `{fr, en}` pair per field (category/question/answer) rather than flowing through the shared `js/i18n.js` STRINGS dictionary — kept structured bilingual content colocated with its data record. Confirmed as an acceptable architectural choice (not a bug) by `goal-evaluator` after review.
- **2026-09-22** — The language toggle reuses the site's existing `.pill-option` CSS pattern (originally built for priority/status pills) as a modifier class (`.pill-option.lang-pill`), not a parallel duplicate class set — a first draft violated this and was caught and fixed via the Completion Loop.
- **2026-09-22** — Login-state/passphrase guards that must prevent any flash of protected content must live in a blocking `<head>` script (`window.location.replace(...)` before `<body>` parses), not a body-bottom script — a body-bottom guard is logically correct but still lets the page paint first, which was reported and corrected as a real bug, not a nitpick.
- **2026-09-22** — HR and IT are separate departments structurally identical to Admin but fully isolated (own ticket queue, own team roster, own login/passphrase session), reached via a nav dropdown ("Espace équipe") rather than a toggle or shared queue — per explicit user choice among proposed options. Department is resolved from the URL path segment (`js/department.js`) and passed explicitly into `Store`/`AdminAuth` rather than self-resolved, so those modules stay usable from public (non-department) pages too. With no build step, `hr/`/`it/` are maintained as content-identical copies of `admin/`'s HTML, verified via `diff` after each edit.
- **2026-09-22** — FAQ authorship is Admin-only: the public FAQ (`kb.html`) filters through 4 categories (Getting started / Your ticket / IT questions / HR questions) via a pill control, but only `admin/faq.html` (no `hr/`/`it/` equivalent) can add or remove entries. Admin-submitted Q&A is single-language (mirrored across FR/EN display) rather than hand-translated like the static seed content, and stored separately in `js/kb-store.js` so it merges with but never overwrites the static `data/kb.js` seed articles. This supersedes the earlier 2026-09-11 "KB is not admin-editable" note.
- **2026-09-24** — Non-index public pages (`status.html`, `kb.html`) moved into a `public/` folder; `index.html` stays at the project root as the static host's default document. Rejected merging them into one `index.html` (SPA-style section toggling would add a bug class — wrong section visible — that the current multi-page structure doesn't have); the `public/` folder instead establishes a home for future public pages before they pile up loose at the root.
