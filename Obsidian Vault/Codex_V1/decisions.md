- **2026-09-17** ("Internal ideas and improvement hub") — Added a second page, `library.html`: a sandbox for testing/storing visual assets (background/motion effects) before they'd be considered for the live site. Each asset is a self-contained "asset block" (card + demo + pop-up modal with a larger demo), and each block gets its own dedicated modal rather than one shared modal — a shared modal only works for exactly one block; a second, structurally different block needs either a content-cloning fill function or a modal per block, and the latter matches the codebase's existing explicit-named-controller style.
- **2026-09-17** (factory-wide, applies to future unrelated Codex_V1 projects) — Process/workflow lessons from this session: (1) never trust a subagent's self-report — independently re-verify live (e.g. via Playwright), not just by re-reading files; (2) only the lead agent should dispatch `goal-evaluator` before declaring work done, a subagent's own nested self-check isn't authoritative; (3) watch for CSS shorthand-property cascade collisions — two selectors on the same element both declaring the same shorthand (`display`, `transition`, etc.) don't merge, only one wins the cascade; (4) apply design-token discipline proactively while writing new CSS, not reactively after a `goal-evaluator` block; (5) verify a "reusable template" component against at least two real instances before trusting it as proven, since a single instance can hide bugs that only appear at N=2.
- **2026-09-17** — New, unrelated sub-project added to Codex_V1's root: **"Customer support ticketing system"** — a static (localStorage-only) helpdesk site (public ticket form, status lookup, KB, admin login/dashboard/team/ticket-detail). Files in it that duplicated/conflicted with root tooling (`.claude/`, CLAUDE.md, `.venv/`, scripts, unrelated video-pipeline assets) were staged into a `Remove/` subfolder for the user to delete manually, not deleted directly.
- **2026-09-17** ("Customer support ticketing system") — Visual design direction changed from a Basecamp-influenced warm/tactile palette (cream bg, burnt-orange accent, color-pill priority) to a technical/precise Zendesk Garden/Intercom-grounded palette (cool blue `#1F73B7` accent, neutral greys, hairline borders, segmented-control priority picker) — user's explicit choice during design-canvas intake. The retired palette was saved as the `helpdesk-utilitarian` variant of the design-canvas `warm-tactile` template rather than discarded.
- **2026-09-17** (factory-wide, applies to future unrelated Codex_V1 projects) — `design-canvas/extract_tokens.py` must be scoped to the actual stylesheet directory (e.g. `.../css`), never run against a project root that still contains a staged-for-deletion `Remove/` folder or other unrelated assets — this silently contaminates `design-tokens.json`/`.md` with unrelated CSS custom properties, and has now recurred once within the same project after already being documented once.
- **2026-09-17** ("Internal ideas and improvement hub") — Canvas `globalCompositeOperation = 'lighten'` is a one-way brightness ratchet when paired with a background trail-fade: it can only raise a pixel toward the lighter value, never lower it, so a light background eventually saturates to solid white and a dark background's revisited paths lock into static bright spots instead of flowing/fading. Any canvas effect that needs genuine ongoing motion (not a one-off flash) should use normal `'source-over'` blending so the trail-fade can pull brightness back down every frame; this class of bug is only visible over a long window (10s+), not in the first few seconds.
- **2026-09-21** (factory-wide, applies to future unrelated Codex_V1 projects) — A new empty named subfolder appearing in Codex_V1's root, or a subfolder that a prior vault log/session described no longer being present on disk, is normal factory-workspace turnover (a new project starting, or a finished one moved elsewhere) — not an error or a vault/disk sync conflict. The same applies if an older, previously-existing project folder is brought back into the root. Never flag any of these as a discrepancy during `/vault-resume` or similar checks; treat current disk state as the current project scope and proceed without asking for confirmation on this point.
